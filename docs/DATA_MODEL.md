# PharmaTrack v2 — Data Model

> Target: PostgreSQL 16 via **Prisma**. This document is the source of truth for
> `backend/prisma/schema.prisma`. Field names below are the **Prisma (camelCase)**
> names; actual column names are snake_case (Prisma `@map`).

## Conventions

- **IDs**: UUID strings generated by Prisma. Keeps the old project's property
  that offline-generated records never collide — relevant if data is ever
  migrated or distributed.
- **Timestamps**: native `DateTime` (`timestamptz` in PostgreSQL) instead of the
  old `TEXT`/`datetime('now')` strings.
- **Money / coordinates**: `Decimal` (`@db.Decimal(10,2)` for FCFA prices,
  `@db.Decimal(9,6)` for lat/lng) instead of `REAL` floats.
- **Booleans**: real PostgreSQL `boolean` instead of `0/1` integers.
- **Status & type fields**: PostgreSQL `enum`s instead of magic strings.
- All write paths validate through Zod and are scoped to the caller's pharmacy.

## Enums

| Enum | Values | Purpose |
|---|---|---|
| `Role` | `ADMIN`, `PHARMACY`, `USER` | Account role. `PHARMACY` replaces the old `pharmacist`/`pharmacy` naming split; the UI may label it "Pharmacist". |
| `PharmacyStatus` | `PENDING`, `ACTIVE`, `SUSPENDED`, `REJECTED`, `DELETED` | Lifecycle of a pharmacy tenant. `DELETED` is a soft delete. |
| `UserStatus` | `ACTIVE`, `PENDING`, `SUSPENDED` | Account login gating. |

| `AdjustmentDirection` | `INCREASE`, `DECREASE` | Only present/used for `ADJUSTMENT` movements. |

Relations: `batch ProductBatch`, `performedBy User?`, `approvedBy User?`,
`lossReport LossReport?`.

**Sign convention (derived):**

| Type / direction | Effect on batch stock |
|---|---|
| `RECEIPT`, `RETURN`, `ADJUSTMENT + INCREASE` | **+** |
| `SALE`, `TRANSFER`, `DESTRUCTION`, `LOSS`, `ADJUSTMENT + DECREASE` | **−** |

Invariants (service-enforced):
- A stock-out movement (`SALE`, `DESTRUCTION`, `LOSS`, `TRANSFER`,
  `ADJUSTMENT−`) may not drive a batch below zero.
- `LOSS` automatically creates a linked `LossReport` with the movement's reason
  as `circumstances`.
- Deliberately **no delete** for movements: the lot history is an audit trail.

## Indexes

Mirror the old schema and add tenant-scoped lookups:

- `product` : `pharmacy_id` (FK index), `@@unique([pharmacy_id, barcode])`
- `product_batch` : `product_id`, `(product_id, expiry_date)`
- `stock_movement` : `batch_id`, `occurred_at`
- `loss_report` : `movement_id` (unique FK)
- `refresh_token` : `user_id`, `jti (unique)`, `expires_at`
- `revoked_access_token` : `expires_at`
- `login_attempt` : `(scope, key)` (composite PK)
- `users` : `pharmacy_id`

## Seed (optional, `prisma/seed.js`)

Idempotent demo seed enabled by `SEED_DEMO=true` (like the old project):
- 2–3 demo pharmacies (incl. the default tenant), an `ADMIN` account,
  pharmacy accounts, and ~10 medicines with batches and movements.
- Deterministic IDs + upserts so repeated runs are safe.

## Notes / decisions

1. `ADMIN` accounts have `pharmacyId = null` (platform-wide). If a platform
   admin later needs to act *inside* a pharmacy, we pass `pharmacyId` explicitly
   and the tenant-scope check is loosened only for role `ADMIN`.
2. `openingHours` is JSON for symmetry with the old payloads; it is not
   queried. If it ever is, promote to concrete `time` columns.
3. Exact stock is never in a public projection; `inStock` is computed in the
   service from batch sums.
4. Prices are `Decimal(10,2)` in FCFA. API serializes them as strings in JSON to
   avoid float precision loss (see `API.md`).
